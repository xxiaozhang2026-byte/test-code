# 19 V0.2 立项依据｜第二节：研究问题与研究内容

> **定位**：立项依据**第二节**。承接 [[18 V0.2立项依据_第一节_20260917]]——第一节完成"**为什么做**"，本节正式回答"**究竟研究什么**"。
> **与第一节的闭合**：第一节收束于核心未知——**既有营建解释所指向的空间关系，在动态洪涝过程中获得何种性能证据？这些证据支持、限定还是修正既有建筑学认识？** 本节把这一问拆为三个可执行的研究问题，并使证据逐级递进。
> **判断骨架**：[[jijin-luoji]] ch06（研究链三条件＝不可跳过的顺序／明确的单元接口／可检验的阶段结果；**真闭环的标志是结果"回用"，不是箭头多少**）。
> **约束**：[[16 省自科申报书_语言与图表写作规范_V1.0_20260916]]。

## 结构定位：研究链的转换

本节的核心转换只在一条判断上：

> **不是"识别—模拟—评价"，而是"解释—预期—证据—更新"。**

| | 一般技术流程 | 本项目研究链 |
|---|---|---|
| 起点 | 形态识别 | **既有营建解释** |
| 中间 | 洪涝模拟 | **性能预期 → 动态证据** |
| 终点 | 综合评价 | **解释更新（支持／限定／修正）** |
| 学科主语 | 方法 | **建筑学认识** |

一般技术流程的每一步都能独立完成，但**后一步并不改写前一步的判断**：形态识别不检验营建解释，模拟结果不检验性能预期，综合评价不返回建筑学认识。本项目的研究链以**回用**为标志——2.2 的动态证据必须返回 2.1 的营建关系，并改写其原有解释。

> **术语纪律（2026-09-17 定，本节起固定）**：
> - 2.2 的交付物统一称「**可定位至具体空间关系的动态性能证据**」，后续正文不再使用"量化结果""模型结果"等泛称——以持续强化建筑学主语。**此名仅指证据角色，不代表结果变量或上位概念已经冻结；后二者仍待概念与测度文献核验。**
> - 涉及成立限度一律用「**成立范围**」或「**证据支持范围**」，**不使用**"适用条件""边界""阈值""临界"。
> - 三结局固定为「**支持／限定／修正**」，与第一节（四）（六）同辞。
> - **两层纪律（勿混，2026-09-17 定）**：「**动态性能证据**」是**证据角色名称**，**不等同于已冻结的结果变量或综合评价概念**。**证据角色＝已定；结果变量与上位概念名称＝未定**——其具体观测量、测度方式及上位概念名称（洪涝性能／洪涝响应／抗扰—耐受性能／适应性能……）**仍待概念与测度文献核验**。本节命名**不构成** [[10 项目内核]] §4.3 顺序纪律的提前穿透，**认识门未被穿透**。

## 2.1 既有营建解释所指向的可观测空间关系及其性能预期

既有建筑学与聚落研究对传统村落的水环境适应已积累功能层面的解释，但这些解释多以整体性、经验性的方式表述，尚不足以直接进入性能检验。本部分的任务是：**从既有营建解释中识别具有明确空间指向且可观测的营建关系**，并把每条关系所隐含的功能判断转写为**可检验的性能预期**。

操作分两步。

第一步，从文献、史料与地方营建经验中提取营建解释，按**空间关系的组织方式**归并，例如避水关系、导排关系、容蓄关系、围护关系。

（内部注记：关系类型仅作形态预期表的组织方式；**不得演化为村落分类体系**，以免穿透 [[13 三案例可比性审计表]]。）

第二步，对每条关系确定三项内容：

- **可观测变量**：该关系在形态上如何被测量（位置、规模、走向、高程关系、连通关系等）；
- **功能指向**：既有解释认为它应对的是哪一种水环境过程；
- **性能预期**：若该功能成立，在给定扰动条件下应当观察到何种响应。

**交付物＝形态预期表**：以**空间营建关系**为行，以"既有营建解释—可观测变量—功能指向—性能预期"为列。**表的每一行即一条待检验命题**；表中所有形态变量必须落在可直接测量的形态事实上，与历史／口述层的功能解释严格分列（[[11 数据准入闸门表]] 门一）。

**接口**：输出进入 2.2——每一条性能预期对应一组待获取的动态响应。

> **形态预期表结构**（**V0.1 试填稿见 [[20 RC1形态预期表_V0.1_20260917]]**）
>
> | 案例 | 空间营建关系 | 可观测形态变量 | 既有功能解释（含出处） | 功能指向的水环境过程 | 性能预期（可证伪表述） | 证据来源等级 |
> |---|---|---|---|---|---|---|
>
> 说明：①「既有功能解释」须带可核验出处，落在 [[02 立项依据]] 的安全条目上；②「性能预期」须写成**在某扰动条件下应出现／不应出现某种响应**的形式，否则 2.3 无法对应；③「证据来源等级」按形态事实／历史材料与功能解释分列，不得混栏。
>
> **V0.1 试填的两条结论**：① **可行**——7 行空间营建关系（台基—院落、街巷—水系、塘池—汇水、圩堤—围护、围护—内部排水、岸线—街巷退让、洲体—围护）均可写出可测变量与可证伪预期，"解释→预期→证据→更新"在建筑学层面可执行；② **卡点**——「既有功能解释」列**无一条有出处**：[[02 立项依据]] 24 条文献中**没有一条以三村为研究对象**，[[11 数据准入闸门表]] **M8 三村全部【待协调】**。**RC1 的可执行性取决于 M8 是否启动**；M8 不落实，2.3 检验的将是本项目自拟假设而非既有建筑学解释。

## 2.2 不同扰动条件下空间营建关系的动态响应

本部分把 2.1 的性能预期置于动态洪涝过程中，回答：**这些关系在不同扰动条件下实际呈现怎样的动态响应？**

**对象**：结合查济、西河、大通各自的地形、水系及外部水位条件，本项目为三个案例各自建立与其水环境约束相对应的动态模型，获得各案例内部可定位的性能证据。三者为同一建筑学问题提供**异质的发生语境**。

（内部注记：安全逻辑链＝**案例名称 → 各案例实际水环境约束 → 相应扰动情景 → 各案例内部可定位的动态证据**；**不得写成"三类村落 → 统一指标 → 横向比较 → 类型差异"**——后者才是被 [[13 三案例可比性审计表]] 卡住的一步。句式上**避免"分别对应……"**，该句式会在语言上自动生成三分类型。）

**扰动条件**：以重现期或降雨—水位组合表示的情景集，量级取用**既有规范、文献与地方营建经验所给定的取值**，使情景取值可复核。

**操作**：建立能够反映空间营建关系的动态模型，逐一改变或关闭 2.1 表中的空间要素（塘池、沟渠、街巷、台基、圩堤等），获取响应的差异。三案例共享同一分析协议——同一形态变量定义、同一转译原则、同一情景集组织方式、同一输出逻辑。

**交付物＝可定位至具体空间关系的动态性能证据**：每一条证据都能指回 2.1 表中的某一行、某一条营建关系，而非停留在流域或聚落整体的统计输出。

**接口**：输出进入 2.3，逐条对应 2.1 的性能预期。

## 2.3 动态性能证据对既有空间营建解释的检验与更新

本部分把 2.2 的动态证据与 2.1 的性能预期逐条对应，回答：**这些证据对原有营建解释意味着什么？**

**对应分两层。**

- **第一层｜逐扰动条件**：在每一扰动条件下，比较某条空间关系的实际响应与其性能预期，得到「一致／不一致」的判断。
- **第二层｜跨扰动条件**：同一关系在不同扰动条件下的响应是否稳定，得到「稳定／改变」的判断。

两层组合形成四种结果状态。

**回译**：四种结果状态按建筑学意义归入三类结局——

- **支持**：原有解释在该关系上获得性能证据支撑；
- **限定**：原有解释只在部分扰动条件或一定证据范围内成立，需明确其**成立范围**；
- **修正**：原有解释与原功能判断不符，需改写。

**交付物＝逐关系的解释更新判断**：2.1 表中每一行获得一条结论，其判据（哪一条件、哪一响应、与哪一预期比较）可复核。

**接口**：向上回到 2.1 的营建关系，形成研究链的闭合；向外构成研究内容与创新点的落点。

## 2.4 三个研究问题的证据递进与接口关系

三个问题构成**不可跳过的顺序**，每一环的证据是下一环的输入：

| | 研究问题 | 阶段结果 | 下游接口 |
|---|---|---|---|
| **2.1** | 既有营建解释指向哪些**可观测**空间关系？可预置什么性能预期？ | 形态预期表（逐行＝待检验命题） | → 为 2.2 提供待检预期 |
| **2.2** | 这些关系在不同扰动条件下呈现怎样的**动态响应**？ | 可定位至具体空间关系的动态性能证据 | → 为 2.3 提供检验对象 |
| **2.3** | 动态证据与预置预期如何对应？怎样返回建筑学解释？ | 逐关系的解释更新判断（支持／限定／修正） | → 回到 2.1 的营建关系（闭环） |

三者的**不可跳过性**在于：若无 2.1 的预期，2.2 的动态结果无从对应；若无 2.2 的证据，2.3 的检验无从进行；若无 2.3 的回译，前两步不改变任何建筑学认识。

**由此，项目形成"既有营建解释—性能预期—动态证据—解释更新"的完整研究链，而不是"形态识别—洪涝模拟—综合评价"的一般技术流程。**
